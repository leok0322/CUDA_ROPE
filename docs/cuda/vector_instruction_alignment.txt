================================================================================
  CUDA 向量指令与字节对齐
================================================================================

--------------------------------------------------------------------------------
一、为什么需要对齐
--------------------------------------------------------------------------------

  CUDA 向量指令（ld.v4.f32、st.v2.f64 等）要求操作地址是指令宽度的整数倍。
  若地址不满足对齐要求，硬件会触发 misaligned access 错误或退化为多条标量指令。

  对齐要求 = 单次指令传输的字节数：
    16 字节指令 → 地址必须是 16 的倍数
    8  字节指令 → 地址必须是 8  的倍数

--------------------------------------------------------------------------------
二、PTX 向量指令上限：128-bit（16 字节）
--------------------------------------------------------------------------------

  CUDA PTX 对所有元素类型的向量指令上限均为 128-bit（16 字节），
  没有 256-bit 的向量加载/存储指令（即不存在 ld.v4.f64 / ld.v8.f32）。

  ┌──────────┬─────────────────────┬──────────────┬──────────────┐
  │ 元素类型 │ 最大向量指令        │ 向量宽度     │ 对齐要求     │
  ├──────────┼─────────────────────┼──────────────┼──────────────┤
  │ f16      │ ld.v4.f16  (half4)  │ 4×2 =  8 字节│  8 字节      │
  │          │ ld.v8.f16  (half8)  │ 8×2 = 16 字节│ 16 字节      │
  ├──────────┼─────────────────────┼──────────────┼──────────────┤
  │ f32      │ ld.v4.f32  (float4) │ 4×4 = 16 字节│ 16 字节      │
  ├──────────┼─────────────────────┼──────────────┼──────────────┤
  │ f64      │ ld.v2.f64  (double2)│ 2×8 = 16 字节│ 16 字节      │
  │          │ ld.v4.f64  ✗ 不存在 │              │              │
  └──────────┴─────────────────────┴──────────────┴──────────────┘

  结论：无论 float 还是 double，最宽向量指令均为 128-bit，对齐要求均为 16 字节。
  __align__(16) 对两种类型都足够，不需要根据 scalar_t 调整。

  常见误解：
    double 元素是 8 字节，4 个 double = 32 字节 → 需要 32 字节对齐？
    错误。PTX 不支持 ld.v4.f64，double 最多打包 2 个（double2 = 16 字节），
    对齐要求仍是 16 字节。

--------------------------------------------------------------------------------
三、全局内存 vs 共享内存的对齐
--------------------------------------------------------------------------------

  3.1 全局内存（Global Memory）
  ─────────────────────────────
    向量化加载指令要求地址 16 字节对齐：
      ld.global.v4.f32  {r0,r1,r2,r3}, [addr]   // addr % 16 == 0
      ld.global.v2.f64  {r0,r1},       [addr]   // addr % 16 == 0
      ld.global.cs.v4.f32 ...                    // 同上，.cs 只影响 cache 行为

    cudaMalloc 分配的内存至少 256 字节对齐，满足所有向量指令的要求。
    手动分配时需保证起始地址 16 字节对齐（或使用 __align__ 属性）。

  3.2 共享内存（Shared Memory）
  ──────────────────────────────
    静态 SMEM：
      __shared__ float  arr[N];        // 编译器自动 4 字节对齐
      __shared__ float4 arr[N];        // 编译器自动 16 字节对齐

    动态 SMEM：
      extern __shared__ char smem_raw[];           // 1 字节对齐（不够）
      extern __shared__ __align__(16) char smem_raw[];  // 显式 16 字节对齐 ✓

    动态 SMEM 必须手动指定 __align__(16)，否则编译器只保证 char 的 1 字节对齐，
    后续 reinterpret_cast 到 float4/double2 时访问可能不对齐。

--------------------------------------------------------------------------------
四、__align__ 属性说明
--------------------------------------------------------------------------------

  __align__(N) 的作用：
    告知编译器将变量的起始地址放在 N 字节对齐的位置。
    N 必须是 2 的幂次（1, 2, 4, 8, 16, 32, 64）。

  仅影响基地址，不影响数组内部布局：
    extern __shared__ __align__(16) char smem_raw[];
    // smem_raw[0] 的地址 % 16 == 0  ✓
    // smem_raw[1] 的地址 % 16 == 1  （内部元素不保证对齐，需要通过指针算术对齐）

  实际使用中，切分出的子区域偏移量也必须是 16 的倍数，
  才能保证每个子区域的起始地址满足向量指令对齐要求：

    // totalCol/4 个 [5] 块，每块 5×4=20 字节，gcd(20,16)=4，偏移不总是 16 的倍数
    // stride-5 布局本身无法保证每个 col 的起始地址 16 字节对齐
    // __align__(16) 只保证 smem_raw[0] 对齐，不保证 smemWeight[col] 对齐
